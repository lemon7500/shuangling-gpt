# 我们的日常：共同手记讨论稿

日期：2026-10-28。用户已确认本地首版方向，现已完成实现、验收和本机安装。原有六篇角色短篇保留，未改变动画；下文保留实施前的讨论与设计缘由，实际行为及操作以[霜白小工具使用说明](COMPANION-DESK.md)为准。

## 目标

让霜铃与你积累可以回应、回看和接续的共同经历。每天的一页由少量真实片段和霜铃的克制表达组成，你也能留下自己的声音。她有自己的观察与兴趣，仍是平等的友伴。

用户已选择的内容来源是本地任务记录与主动保存的书签。任务状态只能确认运行、等待、本轮结束等事件；具体做了什么主要依靠主动保存的文字。“本轮结束”不能写成“项目完成”，中断和停下不能推断为疲惫或失落。

## 三次有来有往的互动

### 1. 把这一刻夹进书里

在书签中增加轻量的“值得记住”“下次继续”标记，仍可只写一句话。保存时，霜铃回应一次，例如“好，我给这一页留个位置。”先复用现有动作。

本地可确认的事件只作为补充，例如完成一段专注。日常手记选取少量片段；用户可以排除某个片段，避免把每次工具调用都记进来。现有程序没有完整经历账本，需要从功能启用后新增小型本地记录，不能把已有瞬时通知当作完整历史。

### 2. 昨天那一页，我们一起补完

手记保留现有六篇固定故事，分为“霜境往事”和新增“我们的日常”。每日页建议100–180字，下方提供“补一句”“留到下次”及编辑、删除入口。

“补一句”以用户自己的署名保存，不由霜铃代替用户表达心情。霜铃可以有抒情的感想，但每件工作事实应能追溯到相应事件或书签。

每天首次打开 Codex 时，若昨天有新手记，只轻提示一次：“昨天那一页，我写好了。要一起看看吗？”提供“看看 / 稍后”。不强制开窗，不唤出隐藏的桌宠；正在忙时延后提示，多个窗口和重启不重复提醒。

### 3. 从上次的书签接着走

带有“下次继续”的书签，可在合适的空闲时机出现一次轻问候：“上次夹住的那一页，今天想接着写吗？”提供“打开书签 / 还先放着 / 已告一段落”。选择只更新书签和共同记录，不自动启动任务。

后续手记可以引用同一条书签的真实进展，让共同经历有延续。霜铃也可偶尔分享与当前片段相合的书库小事；此类内容标为角色表达，不编造现实经历。休息、拒绝和暂时不回应都正常，不加入打卡惩罚或亲密度压力。

## 实现路径

| 路径 | 体验与代价 | 建议 |
| --- | --- | --- |
| 本地记录＋预写的角色叙述组合 | 自动整理已确认片段，不调用外部模型、不消耗生成积分。文字变化有限，无法深入理解书签语义 | 第一版先做，优先验证互动是否有趣 |
| 本地草稿＋主动请求AI润色 | 用户选定片段后，主动交给AI补写或润色；语言更丰富，读取范围可控 | 作为后续可选入口，先确定交互方式 |
| 自动AI写作 | 可生成更有变化的日记，但需另选服务、确认费用及传输范围，仍需事实校验 | 不随第一版默认启用 |

“每天自动记录”和“首次打开时提示”建议分成两个开关，均默认开启。关闭记录后停止新采集与生成，旧手记保留；只关闭提示仍可主动阅读。无可用片段时不硬写工作，没有记录的过去也不补造。

按本地日期去重；同一页不会因切换聊天、重启或再次打开被覆盖。历史手记可编辑、删除。删除被引用的书签时，应同时提供移除手记中引用文字的选项，避免只删一处却留下文字副本。

## 假设示例

下例仅演示语气，并非实际昨日记录。

已确认片段：一段25分钟专注结束；主动书签写“明天继续整理控制面板”。

> 昨天，一段专注结束后，你给“整理控制面板”夹上了书签。我起初想把这一页写满，后来还是留了几行。下一步已经有了位置，空白便不显得那么着急。今天若想继续，我们就从那个折角翻开。

用户可以补一句：“昨天最满意的是终于想清楚布局。”这条回应会留在当天页面，也能成为以后再次提起这件事的依据。

## 评审重点

- 是否让用户有表达和选择的机会，而不是单方面收到总结。
- 同一张书签是否能跨日延续，来源和变化是否清楚。
- 是否尊重暂缓、隐藏、关闭及不回应的选择。
- 叙述是否符合霜铃的角色设定，事实是否只来自被允许的本地记录。
- 数据量保持小型；不读取聊天正文、剪贴板或屏幕，不进行隐藏的模型调用。
